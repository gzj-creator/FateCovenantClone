## 2. 目标架构

```
连接层   握手 / 帧 / 会话 / 限流 / 定向推送
派发层   命令注册表（type → 服务、编码、schema、是否回包）
领域层   角色 养成 战斗 任务 社交 公会 抽取 活动 商业
共享层   事件总线 · 属性管线 · 资源事务 · 排行 · 邮件 · 调度器 · 活动生命周期
存储层   SQLite：角色私有表 / 全服共享表 / 账本
运营层   管理端 API + 页面 · 审计日志 · 指标
```

- **命令注册表**取代 110 段 `if`：每条命令声明所属服务、请求编码（ETF/protobuf）、schema、无回包标记。启动时与 1407 目录对账，缺失即启动失败。
- **连接层**：连接上限改为配置项；推送按角色定向（现聊天为全连接广播，转引）；每连接频控。
- 所有写操作保持现有“校验→扣费→发奖→状态→编码”单事务，任一步失败整笔回滚。

## 3. 功能串联：事件总线

事务内同步派发，事件与业务同一事务提交；失败不产生进度。每个事件带 `roleId / 服务器日 / 来源命令 / 幂等键`。

| 事件 | 产生方 | 订阅方 |
| --- | --- | --- |
| `fight.settled`（模式、关卡、胜负、回合、伤害） | 所有战斗模式结算 | 主线/日周任务、成就、活动任务、排行、首周目标、成长之路、公会活跃 |
| `draw.done`（池、次数、产出） | 招募与全部抽取活动 | 招募任务、冲榜、囤货（StockUp）、返现抽、抽取进度奖 |
| `hero.changed`（升级/突破/升星/觉醒/精通） | 英雄养成 | 升星礼包、成长目标、战力榜、图鉴 |
| `equip.changed` | 装备、圣器、幻武、宠物、精灵等 | 属性管线失效、养成任务 |
| `res.consumed` / `res.gained` | 资源事务 | 消费返利、收集兑换、回收活动 |
| `recharge.paid`（商品、金额、代金券） | 钱包 | 累充、首充、月卡、通行证、基金、返利、团购、爆竹累充、VIP 经验 |
| `role.login` / `role.dayChanged` | 登录与跨日 | 签到、七日登录、在线礼包、回归 |
| `guild.acted`（捐献、Boss、探索） | 公会服务 | 公会活跃、公会任务、庭院社交 |
| `power.changed` | 属性管线 | 战力奖励 802、战力榜、阵容快照 |
| `activity.stageChanged` | 生命周期 | 登录模块 92/183 刷新、结算邮件 |

统一统计表：`stat(role_id, key, scope, period, value)`，`scope ∈ 角色/公会/全服`，`period ∈ 永久/日/周/活动期`。任务的 `progress_fun` 一律映射到统计键，不接受客户端自报。全服口径由同表聚合（单人服即该角色真实值，不填固定值）。

接上总线即可解除的拒绝（实测消息含“depend on … counters / aggregate / ledger”）：118001、106203/106205、104601/104602、99401/99402、79103、102906、105501–105504、88942、88921、97501/97502、105702 同类全服任务、DiamondBank 103–114、成长之路 1111–1113、首周目标、功能手册、排行成就 71 行。

## 4. 属性管线与战斗

**属性管线**：`基础(等级×成长) → 星级/突破/品质 → 固定加成 → 百分比加成 → 最终倍率 → 取整`。每个养成系统实现同一接口 `contribute(hero) → {固定, 百分比, 来源}`：装备、团长装备、圣器、Relic、幻武、图鉴、训练、法阵、星魂、命运、纹章、战术、传奇书、阵营光环、宠物、精灵、灵珠、博物馆、称号、皮肤、公会科技。1316 属性查询、1314 战力、战斗输入读同一结果；按英雄缓存，`equip.changed`/`hero.changed` 失效。

**敌方**：按关卡表的队伍、等级、成长、波次生成；无表数据的模式保持拒绝，不再按玩家等级缩放。

**战斗引擎**：补命中/闪避、状态命中/抵抗、反弹、最大生命、`protection/invulnerable/strengthened/frightened/chain/pursuit` 语义；天极值独立资源；召唤、领域、专有层数走专有状态接口。

**战报**：模拟结果一次生成事件流，投影为客户端动作包（行动、伤害 107、Buff 103、死亡、复活、召唤、回合、结束）。未取得 tid 的 Buff 不发包。

**模式接入**：所有 PVE/PVP 模式统一 `resolve(模式, 攻方阵容, 守方来源) → 战报 + fight.settled`。守方来源三类：关卡表、其他角色阵容快照（87701/87702 同表）、机器人表。

**技能门禁**：按等级/星级/突破/精通选择筛选可用技能与倍率，再逐英雄核销 277 条标记。

## 5. 全服与多人层

- **共享表**：排行、公会、拍卖、红包、团购人数、全服活跃、阵容快照、聊天。全部带 `server_id`。
- **调度器**（现状是否存在后台任务：未核）：单进程定时器 + 持久化 `job(key, due_at, done_at)`，启动时补跑漏掉的任务。承担跨日/周重置、赛季冻结、排行发奖、活动结束结算、拍卖成交、邮件过期。重置时点沿用各模块已证实的规则。
- **结算幂等**：`settlement(scope, period, role_id)` 唯一键，重启不重复发奖；奖励走邮件。
- **PVP**：真人不足时由机器人表补位；匹配、淘汰赛对阵、竞猜由调度器按赛程推进。
- **跨服**：先在单服内实现完整规则，跨服聚合留作配置项；多区服进程间不共享写入。

## 7. 活动运营

**生命周期**：`未开始 → 预告 → 进行 → 仅领奖 → 结算 → 关闭`。每个活动实例一行：

```
activity_instance(act_id, family, version, server_id,
                  preview_at, open_at, close_at, claim_until, settle_at,
                  stage, source, override_json)
```

- `source` 区分“表内排期”（开服相对日/参考服平移）与“运营手动”。手动覆盖只写 `override_json`，不改表资产。
- 阶段变化由调度器推进，发 `activity.stageChanged`，同步模块 92/183 并推送在线角色，无需重启。
- 进入“结算”时统一执行：排行发奖、未领奖励补发邮件、周期计数清零、跨期累计保留。
- 每个家族实现同一接口：`loginData / handle(type) / onEvent / settle`。新活动 = 新表资产 + 一个家族模块 + 一行实例。

**管理端新增**（现仅钱包/邮件/代金券）：

| 功能 | 说明 |
| --- | --- |
| 活动面板 | 列表、阶段、时间窗、改期、提前开/关、强制结算；改动留审计 |
| 排期预演 | 给定开服日输出未来 N 天开放活动，复用现有排期审计脚本 |
| 全服邮件 | 按全服/等级/角色列表，带附件，可定时 |
| 公告 | 登录公告、跑马灯 |
| 玩家管理 | 查询、发物品、扣物品、封禁、踢线、重置周期计数 |
| 兑换码 | 批量生成、次数与有效期 |
| 排行 | 查看、手动冻结、补发 |
| 维护模式 | 停止新登录、广播、白名单 |
| 监控 | 在线数、命令错误率、拒绝命令榜（`unsupported_command`、`benefit_command_refused`）、订单、调度器积压 |

**运营流程**：改排期→预演→审计通过→生效；每次结算前自动备份；开新服从档案模板生成日历并跑审计。
