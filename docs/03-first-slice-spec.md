# 3D 小队战斗纵向切片规格

> 版本：0.2
> 更新日期：2026-10-25
> 依据：`analysis/notes/02-battle-evidence.md`
> 状态：原型规则与表现验收基线；独立 C# 测试已通过，Unity 与 Android 尚未验收

> 2026-10-25：本文限定首个 3v3 战斗切片；首个 APK 还包含 R2 图鉴与存档闭环。完整技能、养成、天极角色与法阵的后续范围见 [04-system-roadmap.md](04-system-roadmap.md)，最新源码交付、验证证据和续接步骤见 [05-development-status.md](05-development-status.md)。

## 1. 切片目标

在 Android 上完成一场 3 对 3 的 3D 自动回合战斗，并走通：主界面 → 编队 → 关卡 → 战斗 → 胜利 → 奖励 → 返回主界面。

优先还原“看起来像”和“打起来有反馈”的部分：角色模型、站位、镜头、技能演出、受击和胜负结算。剧情、抽卡、付费、任务系统不进入首版。

## 2. 体验基准

### 必须保留

- 斜俯视 3D 竞技场，敌人远、我方近，双方各三名角色。
- 自动回合战斗，左上角显示回合数。
- 每名角色有生命条；目标被锁定时有明确标记。
- 普攻、受击、暴击/强化、死亡都有独立反馈。
- 至少一名角色拥有带特写、台词和全屏特效的技能。
- 胜利界面展示 MVP、奖励和“确认”。
- 2 倍速和跳过按钮。

### 首版可以简化

- 只实现一个关卡和一套敌人。
- 角色使用自制卡通材质和基础骨骼动画，不追求原游戏精度。
- 只实现一种强化状态，命名和触发规则由项目自定。
- 战斗切片不实现装备、抽卡、日常任务和章节分支；首批图鉴纳入 R2，与首个 APK 一起验收。

## 3. 战斗规则

以下规则是为首版冻结的实现选择；原游戏未确认的部分不得写成事实。

### 3.1 回合与行动

- 战斗按回合推进，每回合所有存活单位按 `speed` 从高到低行动一次；同速先我方后敌方，再按各队阵位顺序行动。
- 单体伤害选择对方存活单位中当前生命比例最低者；同生命比例选较前阵位。群攻选择全部存活敌人，治疗选择最低生命比例的存活队友，护盾作用于自身。
- 当前原型基础伤害为 `max(1, round(attack * 2.6) - floor(defense * 0.5))`，先对攻击乘积取整，再减防御项。最终伤害为 `max(1, round(基础伤害 * 技能倍率 * 战意倍率 * 随机浮动 * 暴击倍率))`。`round` 使用 C# `Math.Round` 默认中点舍入；属性校验要求防御非负。该公式沿用已通过的原型平衡，不是原游戏公式。
- 开场怒气 50；每次普通行动后获得 25 点怒气；怒气达到 100 时，下一次行动改为释放技能并清空怒气。
- 首版不加入手动技能释放；玩家通过编队和角色选择影响战斗。
- 随机数只用于 ±5% 伤害浮动和 10% 暴击，暴击倍率 1.5；使用可注入的种子，同实例重复 `Run()` 也会重置状态与随机源。
- 伤害先消耗护盾，再扣生命；治疗不超过最大生命。护盾保留已有值和本次授予值中的较大者，不相加。最多 15 回合，仍无全灭结果时按双方剩余总生命比例判定，相同比例判我方胜；这是原型保护规则。

### 3.2 强化状态

- 名称暂定“战意”，每次普通伤害行动命中有效目标后增加 1 层，最多 3 层；满 3 层时下一次技能消耗全部层数，伤害技能倍率提高 50%。治疗和护盾数值不受该伤害倍率影响。是否播放特写不改变技能判定或战意累积。
- 这是表现层和规则层的自主设计，不是对原游戏“战意暴走”的数值复刻。

### 3.3 角色原型

| 角色 | 定位 | 普攻 | 技能 | 表现重点 |
| --- | --- | --- | --- | --- |
| 赤刃 | 前排输出 | 单体斩击 | 横斩三名敌人 | 刀光、冲击波、短暂镜头推近 |
| 星盾 / Bulwark | 护卫 | 单体盾击 | 自身护盾 | 金属火花、护盾反馈 |
| 露芽 / Sprout | 治疗 | 单体弹射 | 治疗最低生命比例队友 | 弹道、绿色治疗数字 |

敌人使用同一套数据模型，只替换模型、颜色和技能。

旧版表中的“护盾并嘲讽”“治疗并加攻”未实现，已从当前原型技能承诺中移除。后续按实测证据在 R3 扩展，不把定位名称视为已实现的状态机制。

## 4. 表现规格

### 4.1 场景与镜头

- 竞技场尺寸约 24x16 米，中心战斗区域 14x8 米。
- 相机位于我方后方上方，俯角约 18 至 22 度，正交或低 FOV 透视，保持双方完整入镜。
- 敌我初始间距约 8 米；近战角色在攻击时向目标移动至 1.5 米，再回到阵位。
- 背景使用天空盒、远景浮岛/建筑剪影和地台，不使用高成本实时 GI。

### 4.2 角色与动画

最低动画集：

- Idle：呼吸、衣摆或头发轻微摆动。
- Move：短距离位移。
- Attack：蓄力、挥击、回收。
- Hit：0.2 秒受击抖动和后仰。
- Skill：角色专属蓄力、释放、收势。
- Death：倒地或淡出，血条归零后不再行动。

统一要求：

- 卡通着色、清晰轮廓、暖色边缘光。
- 武器和关键饰件有独立高光或拖尾锚点。
- 角色根部对齐地面，脚底不悬空。
- 同屏总骨骼数、材质数和粒子数设定预算，避免为每个技能复制整套特效。

### 4.3 战斗反馈

- 命中：0.06 至 0.1 秒顿帧、轻微屏幕震动、受击闪白。
- 伤害数字：普通白色、暴击金黄并放大、治疗绿色；从受击点向上飘并淡出。
- 技能：先压暗背景，出现角色横向特写和台词条，再回到战场释放范围特效。
- 强化：角色周围出现持续旋转的能量环，触发时全屏短闪并显示“战意爆发”。
- 胜利：敌人退场，镜头推向我方 MVP，显示大头像、评分和奖励。

### 4.4 性能预算

- 目标 60 fps，最低 30 fps。
- 同时活跃粒子不超过 300；单次技能峰值粒子上限 800，持续不超过 1.2 秒。
- 场上角色最多 6 个，每个角色最多 2 个材质变体。
- 关闭实时阴影或只保留一个主光阴影；远景使用烘焙或纯色。

## 5. 界面流程

```text
Boot（加载）
  → Main（3D 角色展示 + 开始战斗）
  → Squad（三角色编队）
  → Stage（一个关卡卡片）
  → Battle（自动战斗 + 2X/跳过）
  → Result（MVP + 奖励）
  → Main（保存进度）
```

首版只做一套竖屏布局，基准分辨率 1080x1920，适配 16:9 到 20:9。

当前源码的入口为 `Boot → Main`，主界面可进入图鉴、编队与独立 `Stage` 页面；编队页面当前支持交换 3 名初始角色的阵位。主界面和队伍页先进入固定关卡预览，展示敌队、奖励与我方队伍，再由 Challenge 进入战斗。上述流程和布局仍需 Unity Smoke 与设备验证。

## 6. 数据契约

```text
CharacterDefinition
  Id, DisplayName, Role, MaxHp, Attack, Defense, Speed
  BasicSkill, UltimateSkill

SkillDefinition
  Id, DisplayName, Targeting, Effect, Power, HasCutIn

BattleRun / PendingBattle
  TicketId, StageId, Seed, Allies, Enemies, Result
  存档保留规则版本、种子和双方定义 ID 的有序快照

BattleEvent
  Type, Round, ActorDefinitionId, TargetDefinitionId
  ActorInstanceId, TargetInstanceId
  Amount, RemainingHp, RemainingShield, Absorbed
  Rage, WarStacks, Critical, Skill, Note
```

事件类型包含：`BattleStarted`、`RoundStarted`、`ActionStarted`、`Damage`、`Heal`、`Shield`、`StatusChanged`、`UnitDied`、`BattleEnded`。

场上实例 ID 使用 `ally:0` / `enemy:0` 等队伍与阵位标识，双方同一角色定义仍可区分；同队重复定义 ID 会被拒绝。旧 `ActorId` / `TargetId` 字段保留为定义 ID，表现层使用实例 ID 定位对象。`RemainingShield` 属于目标，`Rage` / `WarStacks` 属于行动者，`Absorbed` 是本次伤害被护盾吸收的量。群体技能逐目标输出事件，没有物理时间戳；播放时序由表现层决定。

## 7. 验收场景

1. 从主界面点“开始战斗”，进入固定 3v3 战斗。
2. 每回合按速度行动，伤害、血条、飘字和死亡状态一致。
3. 技能至少播放一次特写和范围特效，不影响最终数值判定。
4. 2 倍速只改变播放速度，不改变战斗结果。
5. 跳过直接显示结算，但战斗事件仍在逻辑层完整结算。
6. 胜利后显示 MVP，奖励写入本地存档，返回主界面仍保留。
7. 同一随机种子重复运行得到相同事件序列。

## 8. 实施顺序

1. 纯 C# 战斗内核和事件日志，不依赖 Unity。
2. 用程序化胶囊/方块角色验证站位、镜头和事件播放。
3. 接入 3 名自制低模角色和动画状态机。
4. 接入技能特写、粒子、伤害飘字和镜头震动。
5. 完成主界面、编队、关卡和结算 UI。
6. 接入版本化本地存档。
7. 在 MuMu 上构建、安装、录制并对照 `battle-02.mp4` 校正节奏。
