# 《命运圣契》个人服务器玩法与运营文档

更新：2026-11-17，执行基线为R1加[R2数值增补](13-numeric-r2-amendment.md)。适用范围：`personal-server/` 与隔离客户端 `com.jzyx.ps`。目标是按本地已取得的原客户端版本逐项还原玩法；Unity 自制游戏路线已经取消。

**用户明确的唯一规则例外：代金券系统保留本项目定制方案。除此之外，所有玩法与运营规则均以原游戏 1:1 为目标。** 代金券的发放、领取和抵扣保留定制，商品内容、限购、活动资格、赠角、关卡及其他规则按原版还原。

**当前没有达到玩法 1:1 验收。** 用户反馈的首章首领错误、引导赠角缺失、2-1 阻断、败北战力显示 0、1 级名人堂引导均作为必须解决的问题登记。本文档规定目标行为、列出原版证据、解释当前实现与差距，不能替代修复和客户端验收。

## 本轮确认的关键事实

1. 首章最后一场战斗 `Section10205 → Fight105 → Team105` 的 NPC 为 `3030500`，关联英雄 `3030501` 蜜雪儿，位置 5。下一节点 `10206` 是剧情，不应继续生成普通战斗。
2. Award1=`1020601×1`在10202通关后领取；Award2=`2020601×1`在2-1通关后领取。旧空配置确实在实际日志拒绝Award1；本轮已恢复原表、合法资格、请求时序、位图、防重和旧档离线修复工具。
3. 原版2-1为`9301600×3 + 9105000×1`、位置`[1,2,3,5]`。本轮普通主线已用Fight/Team/NpcAttr替换地图造怪与玩家均值缩放。临时新库通过首章→赠角上阵→蜜雪儿→剧情→2-1，并验证单人队正常败北、不推进、重登后可重试。NPC精确技能和部分属性能力仍有缺口。
4. 败北战力0已定位到客户端静态NpcAttr.power为0的显示链；已有32/64位离线候选，18项指令测试通过。它不是原服正数算法的恢复证据，未打包安装或进行APK验收，不能只凭服务器def_power就销项。
5. 名人堂1218原条件已恢复为角色等级≥32且开服日≥2，另受模块开关161控制；修复7201错误分组通知和空服创角前门禁。用户1级弹窗的实际触发入口仍待定位，未销项。

这些修复目前只在工作树与临时测试库验证，没有重启实时服务、读写活跃故障库、修改或安装APK。各问题的组件、TCP、存档和客户端验收分别记录于[问题清单](09-defects-and-acceptance.md)，总过程见[实施记录](../../agent/workflow/gameplay-rules-20261114/implementation.md)。

## 统计怎样理解

2026-11-14 重跑派发审计：1407 条命令中，1323 条服务路由、18 条网关直接路由、6 条存在多个所有者、60 条未路由。静态分析提示 172 条请求编码可能不符、982 条编码未确证、223 条响应 schema 缺失。这些是审计线索，**不能换算成玩法完成率**。

历史 `npm test` 的大量通过项主要证明已写实现符合它自己的断言。原版敌阵读取错误、引导奖励为空仍可与这些测试同时存在。因此最终还原必须以原始证据、独立预期结果、真实客户端流程和重登存档共同验收。

## 维护约定

每次修复都在相应章节更新“原版事实 / R1裁定 / 当前实现 / 原证据债务 / 验收记录”。缺原证据的事实身份不改写成已证，执行动作必须引用R1唯一决定，不能继续以“待恢复”回避决定或擅自加等级、概率、价格、倍率和周期。不得用全功能开放、额外送强角、降低敌人属性、强制胜利、清空存档或跳过引导作为 1:1 修复。

本轮统一规则、冲突清理和独立校验见[R1实施记录](../../agent/workflow/rule-baseline-20261115/implementation.md)，此前取证见[11-14记录](../../agent/workflow/gameplay-rules-20261114/implementation.md)。2026-11-06的[历史任务计划](../plans/remaining-gameplay-20261106/README.md)及状态保留，不能继承其旧“未路由/缺表/已完成”结论；它们不再是有效规则入口。
