# 开服前90天排期参数与逐日检查表

这是由完整原配置和本服当前纯时间算法生成的可复查排期参数，**不是已核原服全活动运营日历，也不是可直接force_open的清单**。原配置中可能同时存在不同年代、投放对象和互斥版本。服务器资格、功能/模块开关、服务端排期、世界限制、discard_time与当前实例须另核；生成器不读线上状态。

本服输入：2026-11-12T18:00:00+08:00；参考服：2026-10-01T00:00:00+08:00；模式：schedule。来源：[配置](../../../personal-server/config/activity-calendar-realm-3.json)、[时间函数](../../../personal-server/game/time.mjs)、[窗口计算](../../../personal-server/game/activity-calendar.mjs)、[生命周期](../../../personal-server/game/activity-lifecycle.mjs)。

## 时间口径与使用方法

1. 开服业务日按当前time.serverDay计算。日内05:00为业务日切，00:00为自然日切；开服18:00不能按满24小时才到次日。原FlushTime.GetDayZero的特殊对齐见[时间规则](../activity-rulebooks/time-and-stages.md)，不能与本服naturalDay混用。
2. 原refer_day/server_day与world_time分别登记。正式执行已经裁定世界活动保留原绝对日期；当前代码的平移列只作实现差异核对，不能作为发布输入。历史回放须声明单独统一时间轴。
3. 原state_end_day/state_end_time与ActFrame.stage数组不混用；原阶段算法在显式示例S/E下的结果见[逐活动阶段](activity-phases.md)，0天不自动表示无阶段，空stage不自动补进行期。四项专项明确的R1显式50段是推定输入。
4. 下列“窗口覆盖”仅指当前窗口start≤检查时刻<end，未检查业务资格；数量不等于界面可见数、可玩数或已实现数。
5. 完整原字段及当前函数投影见[JSON](activities.json)。四项执行方案已定，见[动态排期裁定](dynamic-schedule-decisions.md)；末列是唯一R1推定首期事件，和左侧当前实现投影分开。
