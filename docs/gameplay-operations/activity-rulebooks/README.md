## 证据怎么读

- **原表事实**：行号、字段、数组、物品与数量直接来自随项目保存的表；表里有一行，不等于它属于本期，也不等于已证明该字段的运行算法。
- **客户端语义**：已有实施记录引用对应Lua调用链，例如先抽取后领取、五个祈福索引、团购补偿人数、MSB-first位图。仅保留记录真正证明的范围。
- **当前本服**：描述当前源码中的事务、状态表、判断和兼容算法。出现“均匀抽样”“单角色聚合”“本地确定性棋盘”等字样时，属于现有实现边界，不能转写为原版事实。
- **原证据债务**：缺配置、字段解释、事件生产源、服务器聚合、结算或真实客户端样本。事实身份如实记录，具体实施按R1任务裁定，不由常见游戏设计补齐。

“流程”描述现有协议所呈现的操作边界，不自动证明原服执行算法。正文注明“当前”时，扣费、随机、无放回、推进、保底或结算的顺序仅由本服处理器证明；注明“应/必须”而无原Lua消费者证据的内容，是恢复时需满足的数据一致性要求。原表能独立证明的只有明确列出的字段和值。特别是本服随机生成、单角色全服统计和确定性棋盘，均不得据此发布原服玩法说明。

每个家族末尾的协议索引从现有1407条C2S目录按任务卡归组，保留全部命令与请求/回包schema入口。旧任务计划中“未路由”“已完成”的计数是历史快照；本文不继承这些状态。

## 时间、期次与账本约束

活动必须先从 `ActFrameTable.Act` 或 `ActivityTable.Activity` 找到实例，再按 `version` 连接本家族表。`act_id`、配置版本、商品tid、任务tid、奖池tid属于不同键空间，不能因数值相近互换。状态至少按角色和活动实例隔离；按版本存储的旧实现必须另核同版本跨期复用风险。

原特殊日界有消费者证据则优先，缺原特殊规则时采用R1明确的默认UTC+8 05:00；龙岛/助力等已在逐任务中列明的R1例外从其规定。每节“当前日界”只是源码现状，不能自行视为原服已核。正式world_time保留原绝对日期，回放轴另行声明；父子门禁取各自实例，175001不能被父预热一刀切关掉。

抽取产生 `pending` 的活动，开抽只扣费和保存抽中结果，领取才入资源；立即发奖的活动，重放领取只能确认现有状态。领取位、资源、个人累计、操作日志和回包编码应在一个事务完成。中断后从持久化状态恢复，不能重抽一次以补丢失回包。

全服/公会/跨服进度必须来自实际角色、订单、战斗或活动记录。配置明示的补偿人数可以按表增加；除此之外不能用机器人、单角色数据、固定满员或客户端自报总分冒充全服结果。

币种回收、邮件补发、跨期继承有已证原消费者则照原规则；仅有`res_exchange/recover_mail/convert_*`字段不证明换算。其余按R1：旧期余额留账冻结、不能花入新期，确定pending/已支付/已达成固定未领保留原期权益，不编自动邮件或等值钻石。

## 当前文档与实现的共同边界

本次只补充规则文档，没有修改业务、测试、APK或运行服务。历史组件/TCP验证仍以其实施记录日期为准，本册不产生新的APK验收。

已经发现 `all-open` 日历与后续生命周期重评估并非同一层：角色功能锁、原表时间和开服限制仍可能使活动进入 `closed`，模块183还可能删除这些行。因此“all-open仅供测试”也不能解释成“当前运行链必定能展示全部活动”。正式排期、角色资格与结构行保留的目标仍见[活动总章](../07-activities-and-calendar.md)，该实现差距不能通过删掉验收要求消除。

服务存在明确拒绝、兼容算法或未接入进度源的家族，仍是玩法还原的未完成项。本册覆盖145张原待办任务卡及13个当时已有服务家族，共158族；这表示规则与缺口有记录，不表示这些玩法均已可玩。
