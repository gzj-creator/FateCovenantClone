# 06 副本、竞技、社交与公会

## 1. 每个玩法应形成的完整循环

入口与资格 → 当前周期/关卡状态 → 合法编队 → 消耗或挑战票据 → 原版敌阵/真实对手 → 战斗/交互 → 成败与进度 → 实际奖励 → 任务/排名 → 领奖/结束 → 断线重登恢复。

不同模式的战斗入口可以复用属性与引擎，模式规则不能都改成普通主线。例如 BOSS 看伤害而非击杀、塔按层推进、多队按规则计胜场、竞技按真实对手与赛季积分。只回成功、用固定百分比伤害、以战力大小决定胜负均不能作为1:1实现。

本章中文名称沿用已恢复协议目录，最终文案以客户端核实。每个系统全部命令和当前路由见[模块附录](appendices/modules.md)与[命令附录](appendices/commands.md)；2026-11-06 的[战斗任务卡](../plans/remaining-gameplay-20261106/01-battle.md)保留操作分支，但状态已过时。

## 3. PVP、匹配与竞猜

| 玩法族 | 必须实现的玩家流程 | 关键原规则 |
| --- | --- | --- |
| SwapArena | 选择对手、多队/换位、挑战、积分/名次、次数、奖励 | 队伍对位、交换位置、胜负合计、对手快照与更新 |
| HunterArena | 对手刷新、挑战、战报、阶段/赛季奖 | 段位/积分、刷新成本、机器人若原版有则需证明其生成规则 |
| Tournament 巅峰对决 | 报名/匹配、编队、挑战/轮次、任务、榜单与奖 | 真实参与者、轮次与赛程、资格、赛季与冻结 |
| ArenaContest | 参赛、晋级、对阵、观战、竞猜与结算 | 时间窗、赔率/返还、平局/弃权、同人不能重复参赛 |
| TopArena | 资格、半决赛/决赛、观战、竞猜和奖励 | 原晋级和分组、赛程、对手、下注封盘和结果 |
| OverallPVP | 多阶段/淘汰赛、编队、对手、观战/竞猜 | 多队制、淘汰、跨期继承、领奖与冻结快照 |
| PlayMatch/OverallMatch | 入队、匹配、取消、接受、开战、结算 | 同时排队互斥、超时、断线、取消竞态与对手唯一性 |
| TriMatchPVP | 三消战斗、对手、段位、体力/次数、战报 | 不能用普通自动战斗替代棋盘与三消规则 |

对手必须有真实账户/角色与独立状态；原版允许的机器人必须单列来源与字段，不把采集fixture里的96名历史角色当当前服真实人口。空服应返回符合协议的真实空数据或原版配置允许的机器人，不伪造榜单热闹程度。

竞技结算必须绑定本次对手与其对战快照。玩家看到一个对手而服务器拿另一份阵容计算不合格。比赛开始后更换装备、租借到期、退出与重复结算按原版规则处理，不能靠只读当前背包解决。

竞猜、拍卖等先扣后返操作需有冻结/扣款记录和结算凭据。赔率、同分、退款、无效比赛、上限都是待取证规则，不能自定对半分或返两倍。

## 4. 三消战斗独立规则

TriMatchHero、TriMatchEquip、TriMatchLineup、TripleMatchFight、TriMatchTower、TriMatchPVP分别涉及英雄养成、装备交换、阵容、开战/重试/战报、爬塔体力和竞技。它们不是普通英雄背包与普通主线的别名。

需恢复棋盘初始化与合法移动、消除与连锁、回合/行动点、道具、目标、敌人、失败/重试、局内掉落和存档。服务端必须能校验结算来源。客户端提交“过关/分数”不能直接触发任意奖励。任何未恢复的规则逐项保持缺口，不能只用task领取接口充当游戏实现。

## 5. 排行榜、记录与分享

榜单按 `rankId + scope + period + participant` 分区，值来自权威系统；升降序、最小上榜值、人数、同分排序、个人名次与榜外状态按RankTable和消费者核对。角色等级、主线、星数、战力、活动积分、伤害榜分别有不同统计口径。

当前 rank-service 已有rank_entries、备份、真实角色聚合等能力，不能继续引用11-06“所有榜都是空”的旧结论；但属性战力仍有兼容项，跨服、同分规则及各活动接入要逐榜验收。服务默认scope存在`server:1`等兼容默认值，三服必须核实实际调用是否覆盖，避免串服。

通关记录211、点赞212、战报查询/分享应关联真实已提交战斗，含版本、关卡、用时/回合、队伍和作者；不能为没有通过的节点创建通关记录。分享链接/ID要稳定，重复点赞与本人与跨服资格依原版。

赛季结算先冻结榜单，再按原奖励档位生成唯一结算邮件；重启/补跑不再分配名次或重新发一轮奖励。展示期看冻结快照，不能用新赛季实时榜覆盖旧排名。

## 7. 公会基础管理

创建 → 推荐/搜索 → 申请/审批/加入 → 职务与成员 → 捐献/活跃/任务 → 日志/公告 → 退出/踢出/转让/解散。各操作需核原门槛、成本、冷却、容量、职权、加入日限制、离会保留/清除的贡献和活动资格。

公会ID、成员身份、角色module24与公会目录是一套状态，不能只有个人“已加入”而成员表没有。会长转让、解散与正在进行活动要防并发和孤儿数据。公会奖励和个人捐献返利分别记账。

## 9. 验收组合

每个PVE模式至少验证首入、合法挑战、败北、胜利、重复结算、扫荡/领奖、跨期和重登。PVP至少两个真实独立角色，验证对手快照、并发、取消和跨服隔离。公会至少会长、普通成员、外会/未入会三种身份，验证职权、共享进度、奖励与离会边界。无法取得原规则的分支保持明确未完成。
