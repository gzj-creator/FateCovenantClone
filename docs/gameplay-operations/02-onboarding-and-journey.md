## 4. 引导数据结构与请求时序

GuideTable 已读取：Process 141、Step 718、Award 16。关键概念分别是：

- `process_id`：流程 ID；一个 Process 可有多段和多个 key。
- `key_id`：保存的阶段检查点；不一定代表整个 Process 全结束。
- `Step.tid`：具体操作步骤；`GuideAwardStep.ref_int_param` 引用奖励 ID。
- `normal_steps/special_steps`：正常路径和特殊恢复路径；不能任意合并或丢弃。
- `next_process`：后继流程可能有多个，并不保证单线。
- `pb_guide.award`：客户端使用的领奖记录字段，须与实际领取账本同步。

已确认早期链：`102 → 104 → 105 → 106 → 107 → 108 → 109`；102 还指向 113，107 还指向 114。Process104 的 key 为 `[106004,106008]`；Process108 的 key 为 `[110004,110008]`。Process102 key 为 `[102002,102007]`。分支的具体触发语义仍需脚本核实。

原客户端 `GuideAwardStep` 的调用顺序是先请求奖励，成功后 `HandleOver`。本轮已移除“先保存本奖励key”的错误前提，改为检查恢复出的原前驱条件；8001成功不偷偷完成引导，上阵后的8000继续保存相应检查点。

| 命令 | 职责 | 必须保持 |
| --- | --- | --- |
| 8000 `req_save_guide_process` | 保存当前流程检查点 | 验证 Process/key 关系，保留中间/最终语义；不要无条件当整个流程结束 |
| 8001 `req_guide_award` | 领取特定 Award，回真实资源变化 | 正确时序、前驱资格、原子发奖、防重、在线与重登一致 |
| 8002 `req_check_guide_net` | 原客户端引导网络探测 | 当前证据为无响应 schema/无 back 注册的探测；不能随意塞业务状态 |

本轮8000验证Process/key归属，只有该Process最后一个key才is_over=true。104/106004是中间点，104/106008才结束；108同理。旧中间点错误is_over=true在登录投影中修正，晚阶段不会被旧请求倒退，同key属于不同Process时分别保留。这些修复不能直接当作名人堂弹窗根因。

## 7. 体力、首通、扫荡与章节宝箱

规则数据从 `MissionTable` 的 Section、EnergyConst/Max、Sweep/SweepConst、Box、MealAward、Chapter、Boss 读取。需要区分体力自然恢复、购买补充、午晚餐、挑战消耗和扫荡消耗；每种有独立条件与次数。

当前普通战斗在 201 生成未结算战报，207 才扣体力和提交结果；当前失败也扣体力，胜利才推进主线与首通奖励。**失败是否应扣、扣多少及退出是否扣是原版待证项**，不能因为目前如此就写成原版。

扫荡必须已通关；奖励按原配置逐次计算或按原批量规则返回；资源变化、扫荡组数、体力和任务统计对齐。当前 SweepConst 配置为每次 5 体力、EnergyConst 上限 3000，对应协议允许最多 600 次；旧界面按钮一次 10 次是 UI 行为，不应硬套为所有请求上限。这些值的适用版本由表哈希限定。

章节宝箱按已通过关数判断，包括当前已经通关节点；领取位与 `reward_claims` 同步，单领与一键领重叠不能重复发。章节/全服 BOSS 奖励与普通首通不是同一领取类型，不可混用。

## 9. 中断与已受影响存档

在领奖前、数据库提交后回包前、领奖展示中、上阵前、战斗中、207 前后分别断线，重登后都应继续到正确位置。已发奖励不重发，未发奖励可恢复，不能让“引导已结束但角色没有”成为永久状态。

修历史角色必须先保存一致备份和差异，依据合法前驱、领取账本、英雄/资源来源与引导记录计算缺失奖励；输出补发预览、幂等键和范围，保留已获得的正常养成。禁止把角色重建为新号、批量抹功能位或直接改成通关。具体执行验收见[问题与验收](09-defects-and-acceptance.md)。

已提供[离线专项修复工具](../../personal-server/scripts/repair-guide-awards.mjs)：只补合法通关后的Award1/2，领取位或账本存在则跳过；已有英雄但无领取证据标人工核对，不重复发。默认生成脱敏预览，应用需一致备份、源指纹不变、副本演练和完整性检查。发现邻近状态文件的PID活跃时在打开库前拒绝。本轮未读取或修改仍在运行的故障数据库。

新增[journey-fidelity回归](../../personal-server/test/journey-fidelity.test.mjs)使用独立临时库，以正常8001/209/201/207/剧情入口走10202→赠角上阵→10204→蜜雪儿→剧情→2-1：合法单人队败北后不推进、不发胜利奖，重登后原三人队可胜，之后才领取第二名赠角并上阵。全程英雄1级，无额外送角或改怪。它验证当前服务端闭环，不代替原技能/伤害规则与APK连续操作验收。
