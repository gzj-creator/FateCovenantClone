## 用户现象

购买“每日必买返利”或“特惠返利”礼包后，界面仍显示可领取次数 7，但“领取奖励”按钮为灰色。两种返利应采用同一套购买、登录回填和领取口径。

## 调查证据

- 问题模块是 `WishTree` 模块 165，不是 `89501`（`req_cms_data_info`）或 `WishTreasure` 模块 172。
- 客户端命令已核对：
  - `91701 req_wish_tree_draw`：ETF 整数参数，返回 `pb_wish_tree_draw_back`。
  - `91702 req_wish_tree_choose_theme`：ETF 整数参数。
  - `91703 req_wish_tree_rev_treasure`：ETF 整数参数。
  - `91704 req_wish_tree_select`：`pb_wish_tree_select_req`。
- `pb_wish_tree_data` 的关键字段为 `type`、`normal_bin`、`normal_times`、`normal_idx_list`、`accrue_day`、`buy_day_list`、`can_wish_count`；uint64 字段解码为十进制字符串，uint32 索引列表解码为数字。
- `WishTreeMgr` 的 `IsCanDraw` 要求 `can_wish_count > 0` 且 `accrue_day <= 当前天`。`GetRemindCanGetDrawCount` 是 `min(14, 当前天 - accrue_day + 1 - can_wish_count)`，因此界面显示的 7 是“剩余可获得天数”，不是可领取额度。
- `CalAddBuyGiftCount` 读取 `extraParams[3]`，按礼包所属类型把购买日加入 `buy_day_list`；同一类型同一天只增加一次 `can_wish_count`。
- 奖励位按 `award_tid % 1000` 写入 BitBlock，采用客户端同样的 MSB-first 顺序。
- 生产模块 165 的基线为 `accrue_day=20751`，两行 `normal_idx_list` 均存在，但 `buy_day_list` 和 `can_wish_count` 缺失或为零。当前订单证据按类型去重后分别为：
  - type 1（`46003/46002/40009`）：20755、20757，共 2 天。
  - type 2（`40010/40008`）：20754、20755、20757，共 3 天。
- 因而用户购买后只收到金额和礼包奖励，返利模块仍向客户端返回 0 次可领取额度，按钮保持灰色。

## 根因

钱包购买链路没有把返利礼包的购买日写入模块 165，也没有增加 `can_wish_count`。登录时服务端只回放原始模块，缺少对历史订单的回填，因此客户端无法从“购买事实”恢复可领取次数。界面上的 7 次来自提醒天数公式，与按钮条件不是同一字段。

## 已落盘实现

- 新增 `personal-server/config/wish-tree-tables.mjs`：按客户端 `WishTreeTable.data.lua.bin` 固化两种返利类型、礼包映射、9 个普通奖励和自选奖励。
- 新增 `personal-server/game/wish-tree-service.mjs`：
  - 登录时规范化模块 165，保留原 `normal_idx_list` 抽取顺序，并从 `recharge_orders` 回填当前周期内的去重购买日。
  - 回填只接受 `[accrue_day, min(今天, accrue_day + 13)]` 内的日期；过期、未来和上一周期订单不会增加额度。
  - 购买按类型和购买日幂等：同类型同一天重复购买不重复增加 `can_wish_count`。
  - `91701` 校验额度和开奖日，选择下一个未领奖励、发资源、写 BitBlock、扣减额度并递增 `normal_times/today_wish_count`，编码失败由事务回滚。
  - `91704` 持久化特殊奖励自选；`91702` 校验类型；`91703` 尚未实现时返回明确业务错误，不伪造成功。
- `personal-server/game/gateway.mjs` 在登录同步中调用 `wishTree.ensureLoginState()`，并接入 91701–91704；日志只记录类型、奖励和变更数量。
- `personal-server/game/wallet-service.mjs` 在付费购买和 `purchaseGift` 两条路径都记录 WishTree 购买；返利记录固定使用服务端 05:00 日界 `dailyDay(purchasedAt)`。WeekHunt 的正常购买和补购仍保留原有 `extra_params` 日，不会把补购日写进返利周期。
- `personal-server/config/game-tables.mjs` 合并 WishTree 静态表，不改现有活动表。
