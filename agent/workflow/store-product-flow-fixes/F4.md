## 根因

`personal-server/game/item-box-service.mjs` 的 `rule()` 已能识别随机箱和自选箱，但看到 `Designated_Box` 时直接抛出 `Designated box rule is not implemented`。网关的 151/159 路由已经存在，`resources.mjs` 也已有 `2:EmojiItem -> module 6, group 0` 的显式奖励处理器，因此缺口是指定奖励规则本身。

`1151200` 和 `1161200` 同时出现在 `OptionalBox` 与 `Designated_Box`。客户端 `ItemBox.lua` 原型 3 的字节码先比较 `TID_ITEM_DESIGNATED_BOX`，再比较 `TID_ITEM_RANDOM_BOX`、`TID_ITEM_OPTIONAL_BOX`；服务端因此按指定、随机、自选的顺序取规则。

## 实现

- `personal-server/game/item-box-service.mjs`
  - 新增 `designatedRule(tid)`，要求非空 `res_list`，每项必须为合法 `[rewardTid,rewardNum]` 且奖励存在于 `ItemTable`。
  - `rule()` 顺序为指定、随机、自选；指定箱返回 `{ kind: 'designated', awards }`。
  - `open()` 允许 `random` 与 `designated`；每个指定箱按 `num` 重复发放完整 `res_list`，扣箱与 `grantResources` 在同一事务中完成并合并 changes。
  - `open()` 仍拒绝没有选择的 `OptionalBox`；`openSelected()` 对指定箱明确拒绝。
  - 库存不足、非法/空配置、未知奖励和响应编码失败都在事务回滚，不吞箱。
- `personal-server/test/item-box-service.test.mjs`
  - 新增 `1501200` 规则、两箱批量开启、模块 6 group 0、SQLite 重开持久化、指定箱拒绝 selection、编码失败回滚覆盖；并以同时声明两种规则的 `1151200` 验证指定箱优先。
- `personal-server/test/gameplay-gateway.test.mjs`
  - 临时 loopback TCP 增加 type 159 一键开启两箱和 type 151 单箱请求，验证扣箱、两种 EmojiItem 奖励及持久化位置。
