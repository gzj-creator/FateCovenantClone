# F5 主线任务金币等奖励领取

- 状态：主验收通过（组件 + 临时 TCP 集成）；已合入 main，未部署，未做 APK/视觉验收
- 子 agent：F5
- 最后更新：2026-10-31
- 详细证据：[f5-linear-task-destiny-progress.md](../../fixes/f5-linear-task-destiny-progress.md)

## 用户现象

主线任务到达“领取金币等奖励”阶段时，服务端返回业务错误 5；奖励未领取、任务 90 状态未推进。

## 调查证据

- 真实失败链路对应 9010 `req_finish_linear_task`。任务 `10004` 的 `task_type=5901`，配置要求命运阶段 2，奖励为 `201500 × 2000`（金币）。
- `TaskType[5901]` 为 `progress_type=1`、`progress_fun=155`；`MethodTable.DynamicArgs[155]` 指向 `DestinyMgr.RealStage`。
- `DestinyMgr.Init` 把服务器 `pb_destiny_data.cur_stage` 保存为原始 `realStage`；`RealStage` 直接返回该值，不做减一或按已点亮节点计数。
- 登录模块曾由旧 100 迁移到 107。任务进度必须读取模块 107；模块 100 只保留为审计副本，不能作为回退来源。
- 本组配置覆盖 `10004/10020/10030/10041/10055/10069`，分别要求命运阶段 2 至 7。

## 根因

`task-service.mjs` 原来只实现主线 1201 和统计类 `progress_type=2`，没有实现 `DestinyMgr.RealStage` 对应的 `progress_type=1`、`progress_fun=155`，所以六个阶段主线任务都在发奖前被拒绝。

## 实现

- `personal-server/game/task-service.mjs` 新增模块 107 `pb_destiny_data.cur_stage` 读取，只接受 `progress_type=1 && progress_fun=155`。
- 模块缺失、空数据、protobuf 损坏或阶段小于 1 均返回 `GameError(5)`；其他未知进度函数继续明确拒绝，不猜测语义。
- 继续复用 9010 原事务：奖励、`reward_claims`、模块 90 领取位和响应编码在同一事务提交或回滚。

## 验证

- `node --test personal-server/test/task-service.test.mjs`：18/18 通过。
- 临时 TCP 9010 在命运阶段 2 领取 `10004`，返回 `201500 × 2000`；SQLite 重开后模块 90 与模块 107 保持正确。
- 主 agent 在最新 `main` 的 F4/F5 集成 worktree 复测 F4、F5 与 gateway 合计 32/32 通过；全量 `npm test --prefix personal-server` 310/310 通过。
- 覆盖阶段不足、刚好达标、六档奖励、重复领取、模块 107 优先、异常回滚和重开持久化。

## 剩余风险与主 agent 集成项

- F5 代码、测试和状态文档已合入 `main`；尚未部署到实时服务，也未操作隔离 APK。
- 尚未覆盖所有可能的线性任务 `progress_fun`；本任务只实现有客户端和配置证据的 `155`，其他函数仍明确拒绝。
- 真实 APK 中任务按钮、金币提示、模块 90 刷新和重登保持仍需部署后由用户视觉验收。
