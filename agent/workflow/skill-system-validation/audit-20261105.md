## 3. 测试错（改测试，不动数据）

### 3.1 祝福 120000059 断言 maxTriggers 2（1030701、1040201、2020101、3030401）

- 描述：战斗前 2 回合，被治愈率提升 20%。
- 实现：on-round-start + oncePerBattle true + maxTriggers 1，效果为 heal-bonus 0.20、duration 为 timed / rounds 2。
- 判定：实现正确，测试错。证据：同一共享被动在库内 19 个英雄中，7 个英雄的测试断言 maxTriggers 1（1020601、1030501、3020101、3020301、3020401、3030201、4010201），只有这 4 个断言 2。"前 2 回合"由 1 次触发加 2 回合持续表达，不需要触发 2 次，而且实现里 oncePerBattle 为 true，maxTriggers 2 永远用不上。
- 修复：4 个文件的断言改为 maxTriggers 1、oncePerBattle true、triggerType on-round-start、duration timed 2 回合，并去掉标题里的 maxTriggers 2。

## 4. 实现错（改数据）

### 4.1 鹰眼 120000028 丢掉 hp-above-50 条件（1010201、3040101）

- 描述：血量高于 50% 时，命中率提升 15%。库内 19 个英雄里 17 个带 conditionKey 为 hp-above-50，这两个是 null。
- 修复：补 conditionKey。3040101 的测试本来断言这一点，之前一直红灯；1010201 之前没有断言（见 3.4）。

### 4.2 生命护盾 120001003 丢掉 hp-below-70 条件（1020101、5040201、5040401、5040501）

- 描述：首次生命低于 70% 时，获得自身防御力 80% 的护盾，持续 2 回合。这 4 个英雄的触发是 on-hp-threshold 但 conditionKey 为 null，等于任何血量变化都会触发；其余 13 个英雄都是 hp-below-70。
- 修复：补 conditionKey 为 hp-below-70（1020101 同时补 effectType，见 5.2）。

### 4.3 目标类型不在 TARGET_TYPES 词表内（1020601、1030201）

- 1020601 的 6102060102 升格防御写着 front-row-allies。描述是"为我方前排队友施加 5% 最大生命值的护盾"。TargetSelector 没有前排友军类型，default 分支会静默按敌方最前排单体选人，护盾会落到敌人身上。改为 all-allies，标 requiresInvestigation，notes 记录"前排范围无法区分，暂以全体友方近似"。
- 1030201 的 313020175 定制策略写着 front-row-highest-attack，同样没有该类型（会静默变成敌方最前排单体）。改为 single 并标 requiresInvestigation，notes 记录"没有按攻击力排序的前排单体选择器"。
- 未新增目标类型：新增类型要改 target-selector.mjs（效果层），超出本轮只修数据的范围。

### 4.4 timed 持续时间 rounds 为 0（2040101、5040401、5040501）

- 2040101：324010171 龙行 trigger[1]、324010173 罪伞 trigger[2] 与 [3]、324010175 业火 effects[0] 与 [1] 以及 trigger[0] 与 [1] 都是 timed / rounds 0。描述分别是"每回合前两次终结技必定暴击且伤害提升 60%"（按回合计）与"释放终结技时额外附加 10% 暴击率和 15% 暴击伤害"，改为 rounds 1（当回合生效）。
- 5040401 的 354040172 潜能蕴养、5040501 的 354050172 潜能蕴养：每回合开始给全体护盾，描述未限回合数，timed / 0 改为 permanent（护盾持续到被击破）。

### 4.5 用负倍率表达摧毁护盾（5040101）

- 354010174 极意自现用了 shield 效果配 multiplier -0.15。executeShield 只做目标护盾累加，负值会把护盾打到负数，结构校验也不接受非正的 multiplier 或 magnitude。
- 修复：改为 stat-modifier / shield-bonus / -0.15（timed 1 回合），语义是"敌方护盾加成降低 15%"，notes 记录"执行器不支持按比例销毁数值护盾，这是近似"。

### 4.6 蛰伏 120000051 外层 duration 与触发效果不一致（1040201）

- effects[0].duration 是 instant，但 triggers[0].effect.duration 是 permanent，同库其余 15 个英雄都是 permanent。
- 修复：外层改为 permanent。

### 4.7 鼓舞 120000054 缺 on-skill-use（1020601、1030701、2020101、3030401、4010201、5040501）

- 见 3.3。已补齐第二个触发（复制 on-attack 触发的目标与效果）。
- 排除名单内的 9 个英雄（1020401、1020501、1030101、1030501、1030601、3020101、3020301、3020401、3030201）仍是单触发版本，按规则未动，需对应补全组自行对齐。

### 4.8 战斗常驻增益被写成 instant（1020101）

- 1020101 的 6 条技能（312010171 不屈、312010172 健壮、312010173 超群技艺、120000032 反弹、120000042 暴怒、120000044 奋激）描述都是"进入战斗后"或"受到攻击时"提升，同库其他英雄写 permanent，1020101 写 instant。
- 修复：统一改为 permanent / rounds 0。当前执行器忽略外层 duration，这条修复对现行为没有影响，但决定将来接入战斗循环后的表现。

## 5. 元数据错

### 5.1 ability.tid 与 abilityDes.tid 和技能 id 不一致（14 条技能，28 处字段）

- 全库 986 条数字 id 技能中，972 条的 ability.tid 等于技能 id；14 条不等，且这些错误 tid 全部指向其他英雄的真实技能 id（1030501 的 31305xxxx、3110201 的 31102xxxx、33304 与 33203 系列），确认是克隆同系列英雄模板时未替换元数据。
- 分布：1030701 五条（313070171-175 全部指向 31305xxxx）、2030301 四条（323030171-174 指向 31102xxxx）、3030201 五条（333020171-175，属排除名单，未改）。
- 修复：1030701 与 2030301 的 9 条改为自身 id。abilityDes 里的 show_name、text、skill_icon 仍指向模板行，缺少原始文本表无法解析正确值，已在该技能 notes 标注需后续对齐。

### 5.2 effectType、targetType、energyCost 缺失（18 条技能）

- 1020101 全部 14 条技能都缺 effectType（同时缺 targetType 和 energyCost）；4020101、5040201、5040401、5040501 各缺一条（都是 120001003 生命护盾）。
- 修复：按"取 effects[0].effect.type 与 effects[0].target.targetType 机械补齐"的规则填充，energyCost 补 0，notes 标注来源。

### 5.3 描述文本被拼接（3030301、1020201、1030201、1040301）

- 症状：某条技能的 description 结尾原样包含了相邻技能的描述文本，属 dump 的文本表 join 缺陷。检测方式是同英雄内描述互相包含。
- 实例：3030301 的 333030173 直击要害混入 333030174 炽星魔焰的文本（见 5.4）；1020201 的 312020174 伺机待发混入 312020175 蚀骨之痛；1030201 的 313020173 超群技艺混入 313020174 慑魂奇招与 313020175 定制策略；1040301 的 314030174 梦萦魂绕末尾混入 314030175 安魂长眠。
- 修复：按后缀剔除被拼接的相邻描述，保留技能自身文本。四条的实现本来就只覆盖自己的部分，与修复后的描述一致。

### 5.4 3030301 缺整条技能 333030174 炽星魔焰

- 文档与测试都写 14 条技能，数据库只有 13 条（333030171-173 与 175 四系 Mastery，缺 174），描述拼接残留证明该行确实存在过。
- 修复：按描述恢复 333030174：status / burn、chance 0.3、timed 2 回合、on-attack 与 on-skill-use 两个触发、requiresInvestigation（触发概率无法在 processTriggers 里掷骰，燃烧层数不追踪）。无法从拼接文本恢复 ability 行，ability 与 abilityDes 置 null 并在 notes 说明。
- 已知局限：apply-hero-skill-patch.mjs 只支持追加或 insertAfter，该行目前落在技能列表末尾（第 14 位），顺序与天赋编号不连续，但不影响按 id 查找与测试。

### 5.5 effectType 与 effects[0].effect.type 不一致的 5 条（判定合理，未改）

1040101 的 314010172 与 314010173、1040201 的 314020172、1040301 的 314030172、5040101 的 354010172：effectType 是 stat-modifier，但 effects[0] 是 energy（天极值近似为能量损失）。这些是混合效果技能，主效果是增益，任务说明允许"混合效果时 effectType 用主效果类型并在 notes 说明"，notes 已有说明，故保留。

### 5.6 抗暴两种别名并存（未改）

120000034 铁甲：1040101 与 2030101 用 crit-resist，其余英雄用 anti-crit，词表把两者都登记为抗暴。语义等价，未统一，记录备查。

## 8. 未确认项与仍需人工判断的点

1. 数值来源：除描述文字外没有 FightTable.Effect 与 FightTable.Buff 的行数据，所有倍率都是按描述保守取值，不是原服精确值。
2. abilityDes 里的 text、show_name 等本地化 id 仍是模板英雄的值（见 5.1），修正 tid 后这些字段无法自证，需要原始文本表。
3. 120001003 的 maxTriggers 在库内 0 与 1 并存（都配 oncePerBattle true，行为等价），未统一。
4. 3030301 的 333030174 插入位置见 5.4。
5. 1040201、3040201 等"每次行动后为敌方全体施加某状态"的技能，敌方侧状态大多未建模（notes 已标 requiresInvestigation），本轮未补。
6. 概率存放位置不统一：1030401 的 313040174 气定神闲（30%）与 313040175 无声恫吓（50%）把概率只写在 triggers[].chance 上，effects[0].chance 仍是 1。走触发器路径时概率被 processTriggers 忽略，走 skillToEffects 路径时则变成必定触发；两条路径都无法正确表达概率。
7. 1020301 的 312030174 恶性疗法把毒伤定为每回合 20% 最大生命（共约 40%），描述只写"30% 概率附加 1 层中毒，持续 2 回合"，没有伤害数值依据；312030175 恶意蔓延的"额外 10% 暴击率和 15% 暴击伤害"实现为 timed 2 回合且每次终结技无上限叠加，描述没有这两条限定。
8. "附加 1 层"类状态（1020301 的 312030174、1030201 的 313020174）实现为 maxStacks 0、unique false，executeStatus 每次 push 一条独立状态，层数不会按"层"累计。
9. 1020201 的 312020174"自身下一次终结技伤害提升 15%"实现为 1 回合通用 damage-bonus（同时挂 on-attack 与 on-skill-use），普攻触发的增益同样作用于后续普攻，且回合内可重复叠加；"下一次终结技"的消费语义无法用现有触发器表达。

## 9. 系统性缺口与技能库未接入战斗主循环的影响评估

核心事实：game 目录下没有任何模块 import skill-integration.mjs；registerPassiveTriggers、processTriggers、processBuffTicks、applySkillEffects 的唯一调用方是 test/hero-*-skill-validation.test.mjs，battle-engine.mjs 走的是自己的原型逻辑。也就是说，本轮修的 793 条技能数据当前不会影响任何一场真实战斗，修复的价值在于数据结构自洽、测试可信、将来接入时不必返工。

在这个前提下，有几处效果层（不是数据层）的缺陷会让接入后立刻失真，本轮按约定只记录：

1. duration 没有传到执行器。processTriggers 调 executor.executeEffect 时只传内层 effect，而 executeStatModifier 读的是 effect.duration，内层没有该字段，于是所有 timed 增益落到 duration 0，在 processBuffTicks 第一次 tick 就被删除。祝福这类两回合增益接入后会瞬间失效。建议接入时把 wrapper 的 rounds 合并进内层 effect，或让执行器接收整个 wrapper。
2. 触发概率未掷骰。processTriggers 完全不看 trigger.effect.chance，333030174 的 0.3、120000055 的 30% 这类概率触发接入后会变成 100%。
3. 目标类型不支持时静默回退。TargetSelector 的 default 分支只 warn 后按敌方最前排单体选人，"上阵护盾加给敌人"这类错误不会报错。建议改为抛错或返回空数组。
4. applySkillEffects 只应用 effects[0]，混合效果技能（本报告 5.5 那 5 条）接入时只有第一个效果生效。
5. 天极值、层数、状态堆叠未建模。库内用能量 -100 近似 1 点天极值，用 maxStacks 表达层数但执行器不累加，回合结束移除靠 timed 近似。
6. processBuffTicks 的结算时机未与回合流程绑定，tick 顺序（先减 duration 再判定）会让 1 回合增益在当回合就消失，接入时需按回合顺序重新设计。

影响评估：上述 6 项修完之前，把技能库接进 battle-engine.mjs 会得到"数值更丰富但时序和概率错误"的战斗，不如当前原型逻辑可控。这属于战斗引擎与效果层的整体接入工作，超出本轮审查已提交技能数据的范围，建议作为独立任务立项。
