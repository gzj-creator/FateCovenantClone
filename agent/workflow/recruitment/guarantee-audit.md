# 抽取入口保底审计（2026-10-31）

审计范围是个人服务已经接通的抽取、随机宝箱和抽取活动元数据入口。APK 静态目录里还有大量活动抽取命令，但个人服务没有实现这些活动本身；这些入口继续明确返回 `LOCAL_NOT_IMPLEMENTED`，不会以普通随机结果冒充保底。

| 入口 | 记录/状态 | 阈值 | 保底行为 |

半神、特聘和队长装备都使用客户端 `HeroDataMgr:GetRecruitTid()` 的规则：`is_record_by_type=true` 时按 `draw_type` 读写模块 10。这样 UI 的 `GetGuaranteeTimes(drawLib)` 能从真实记录计算剩余次数，重连/重登后也不会回到满值。

随机宝箱的三个阈值由当前配置的 `sum(weight_group) / guaranteed_weight` 向上取整得到。当前只有这三个随机箱带保底配置；该映射是本机兼容规则，客户端资源没有提供独立的原始阈值字段。

## 已验证

- 半神从 39 抽执行五连：第 40 抽标记为保底，结果为 `1200719`，之后模块 10 的 `draw_count=44`、`guaranteed_count=4`，SQLite 重开仍一致。
- 队长装备从 116 的记录 35 抽执行五连：第 40 抽为保底；随后在 117 抽五次仍读取同一 `tid=1031` 记录并累计到 5，不产生第二份记录。
- 随机箱 3501200 在固定随机值下前六次进入普通组，第七次强制保底组并发放 `3002×10`；计数重开保留，编码失败时库存和计数整体回滚。
- 定向招募、特聘、半神、背包和真实网关测试通过；全量 `npm test` 为 `301/301`。
