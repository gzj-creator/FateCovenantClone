## 解码事实

- FunOpen 行的单断言脚本通过 `scriptId -> prototype` 映射后，直接比较模板包含 getter、比较器和阈值三部分。
- MethodTable 的 DynamicArgs 元数据把参数 `1/2/3/4` 分别指向 `GetRoleLv`、`GetPassedSection`、`GetCreateRoleDays`、`GetServerOpenDay`。
- 已证实可执行的 getter 只有 `GetRoleLv -> role_level`、`GetCreateRoleDays -> create_day`、`GetServerOpenDay -> server_day`。
- 比较器 `3/4 -> EGreaterThan`、`5 -> Equals`、`7 -> GreaterThan`、`8 -> ELessThan`、`9 -> LessThan`、`16 -> NotEquals`；本表可执行行当前全部为 `EGreaterThan`，输出 `>=`。
- LuaJIT 33-bit number 使用首字节 bit 0 作为 double/integer 判别、bit 1..6 作为首段值；解析器同时优先采用 header 的精确 upvalue 数量确定常量边界。

## 覆盖结果

- `ready`：164 行。`role_level` 64 行、`server_day` 95 行、`create_day` 5 行；每行恰有一个已证实条件。
- `evidence_gap`：359 行。主要缺口为不支持的表达式 171 行、多断言组合语义未证实 95 行、`GetPassedSection` 未映射 57 行、目标 2 的客户端请求语义 9 行、空断言列表 8 行，以及其余未知 DynamicArg。
- `evaluateFunOpen` 对 `status != ready`、非空 `evidenceGap`、空条件、未知条件和未知比较器均不开放并记录拒绝；不会把证据缺口降级成“无条件开放”。
