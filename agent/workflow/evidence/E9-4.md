## 实现结论

- `ActFrameAct` 配置优先使用 3304；旧 `Activity` 配置使用 3301，与登录侧配置优先级一致。
- 3304 只在状态确有变化时发送真实活动 id、表内 type、实例窗口、当前阶段与阶段进入时间。
- 3301 发送真实 id、退出/进入状态和进入时间；家族专属 `module_*_data` 未经取证时保持缺省，不伪造模块数据。
- `preview/running/claim/show` 分别映射客户端阶段 `10/50/60/90`。这些值在活动状态序列中直接出现；60/90 的业务语义仍受 E10-3 约束。
- `closed` 在客户端表/proto 中没有已证实数值。在线关闭不发送猜测的 stage 0，只记录
  `activity_stage_push_skipped(closed_stage_not_mapped)`；下一次登录从模块 92/183 隐藏。
- 3302/3303 的 schema 与 handler 已证实，但运行时目前没有“精确 pause/custom 变更值”的可信输入，保持不发送。

## 登录同步

- 模块 92：生命周期评估为 `closed` 的活动从 `act_list`、空的并行组、暂停项和定制窗口中移除；可见活动写入权威 `cur_state_id` 与当前状态进入时间。
- 模块 183：同一运行时结果决定 player/server 行是否下发、当前 `cur_stage_id`、overall window 与 `stage_time_list`。只修改本次登录副本，不回写旧登录快照。
- 运营 `extend/force_open` 的有效窗口同时应用到模块 92 已有 custom window 和模块 183；不新增未经 E10-4 证明的家族定制窗口。
