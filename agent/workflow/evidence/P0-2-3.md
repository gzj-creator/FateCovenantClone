## 协议与客户端语义

- `res_notify_fun_open`：`target_tid:int32`、`extra_ret_list:fun_open_to_client[]`。
- `fun_open_to_client`：`flag:int32`、`data:bytes`、`enable_time:uint32`。
- FunOpen 字节码从 `target_list` 读取 `target_tid/fun_open_state`，用该 bitmap 重置目标，
  再调用 `OpenFunAndNotify(extra_ret_list)`；通知处理按 `flag/data/enable_time` 调用 bit
  block 的 `Set`。本轮只为新开放项发送 `flag=1`，表内没有可信启用时间时不发送
  `enable_time`。
- `data` 必须与提交后模块 3 的权威 target bitmap 完全一致，测试对此逐字节校验。
- 未找到“角色等级变化”或“战力变化”专用 S2C 类型。资源/经验变化继续沿用业务响应的
  `pb_res_change.extra=[level,exp]`；属性查询读取失鲜缓存后的新值，不臆造推送。

## 服务实现

- `game/event-bus.mjs` 在事务内排队事件；action 返回后、`writeModel`/`COMMIT` 前同步
  flush 给订阅方。订阅方需要在线推送时注册 `afterCommit`。
- `game-store.transaction` 只在 COMMIT 成功后执行 `afterCommit`；ROLLBACK 丢弃所有回调。
- 角色经验道具奖励和主线结算经验均产生 `role.levelUp`，事件含 roleId、from/to、
  serverDay、source 与幂等键。
- 网关订阅在事务内重算 FunOpen、失效该角色属性/战力缓存，并在 COMMIT 后只向该角色发送
  已证实的 7201。
- `createLineupAttributeCache` 的 key 包含角色等级、编队和英雄成长字段；即使调用方直接
  改模型而未发事件，下一次读取也不会返回旧属性。

## 边界

- 7201 已有解码样本但没有独立用户动作和 APK 视觉验收。
- 不存在已证实的属性/战力专用在线推送；本项只保证缓存正确失效，不能宣称客户端收到
  独立战力变更通知。
- 事件总线目前只接 `role.levelUp`；其他领域事件按后续 P0/P1 项逐个接线。
