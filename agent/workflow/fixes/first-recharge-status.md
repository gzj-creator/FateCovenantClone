# 线性首充购买状态修复

## 现象与原因

2026-10-31 用户购买 ¥6 首充礼包后，英雄已到账，首充面板仍显示支付 ¥6。实际订单商品为 `600078`，对应线性首充第 `31` 档、选项 `3101`，奖励英雄 `5040201`。旧服务已发奖并保存订单，但未把购买写入模块 `547` 的 `buy_list`，客户端因此仍认为第 31 档未购买。

当前配置中下一档为 `tid=32`、`choose_tid=3102`、商品 `600079`，标价 ¥30。该金额来自商品配置，实际客户端显示尚待用户确认。

## 修复

- 本次在 `.worktree/first-recharge-status` 的 `fix/first-recharge-status` 分支工作；起点为 `f32e4ac`，其后合入了更新的 `main@ca19a9b`。该版本已接入线性首充购买事务、`1900` 推送中的 flag 99、`102101/102102` 和登录模块 547。
- 补充历史订单回填：登录同步时，依据商品配置、活动时间和当前角色所属钱包的已提交订单，恢复缺失的 `buy_list` 行并推进当前档位。已有购买行和领取位保留，多次登录不会重复插入。
- 独立的普通首充领取逻辑沿用上述基线。本次新增代码只处理线性首充的历史订单状态。
